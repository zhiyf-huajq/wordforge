一、一句话结论

词匠在最关键的两处其实已经超过市面免费版：① 记忆算法的参数开放度（11 个参数全给你改，市面没有任何一款开放到这个程度，墨墨的算法干脆是黑盒）；② 内置的文章精读（市面只有扇贝阅读有类似能力，且是独立收费 App）。

真正的缺口集中在四个点，而且全部是「离线可做、不碰数据层」的：词汇量测试（学之前不知道该从哪开始）、考试倒计时反推（不知道该每天学多少）、听力题型（六级听力占 35%，现在完全没有练的入口）、形近词辨析（六级选词填空的核心陷阱）。

市面那些看起来最热闹的功能 —— 打卡社区、组队 PK、排行榜、云同步、图片记忆、影视原声例句 —— 要么直接违反「离线可用、数据不上传」这条硬约束，要么在体积和版权上不划算。这一部分应当明确不做，而不是「以后再补」。

四、建议清单

P0 · 强烈推荐（离线可做、价值最高、工作量最小）

1 · 词汇量测试 P0

为什么值得做：现在统计页那个「预估词汇量」是学习结果的副产品 —— 依赖你已经学了多少词、持久度怎么样。而市面的词汇量测试是起点定位：学之前先测一次，然后它回答三个问题 —— 我大概什么水平、该从哪本词书开始、每天该学多少。这三件事恰好在词匠里完全没有入口。

怎么做（纯离线）
从各档位词表分层抽样 30–40 题（中考 / 高考 / 四级 / 六级 / 考研 各抽若干），每题给「认识 / 不认识」，答「认识」的再补一道四选一验证（防自评虚高）。用阶梯法收敛：某一档正确率低于 50% 就停止往下测。最后按档位对词表规模加权求和，得到一个估算区间而不是单一数字。
实现要点
不新增数据结构，直接复用 WORDS + LVL_ORDER；结果只写 DB.cfg 的推荐值，不污染 DB.prog（那是记忆算法地盘）。
参照产品
扇贝「智能词汇量测试」、百词斩「阅读 / 听力词汇量分开测」

2 · 考试倒计时 + 每日量反推 P0

为什么值得做：你现在的设置是「每天新学 20 个」，但 20 这个数字是怎么来的？没人知道。真实场景是反过来的：距离 12 月六级还有 N 天，词库里还剩 M 个没学，所以每天至少要学 M/N 个 —— 而且这个数每过一天都要重算。这是一个纯算术问题，却决定了整个备考节奏。

怎么做
设置里加「考试日期」字段 → 今日总览顶部显示「距考试 83 天 · 建议每日 32 词（当前 20，偏低 12）」→ 一键套用到 newPerDay。剩余量要按「目标词书的总数 − 已学」算，而不是按 I 词库总数。
顺带能做的
按当前 pace 预测「按这个速度，到考试前能学完 X%」，比单纯报数字更有推动力。
参照产品
墨墨（把学习量换算成每日时长）、百词斩「调整计划 → 完成天数」

3 · 听力题型（听音选义 / 听音拼写） P0

为什么值得做：六级听力占 35%，是四项里权重最高的一档。而现在词匠的 4 种题型（英选义 / 中选词 / 拼写 / 卡片）没有一种需要用到耳朵。这意味着「背单词」和「听力」在应用里是两个完全没有交集的技能 —— 这是当前最大的功能空洞。

怎么做
复用现有 TTS（已经支持美/英音 + 语速）。新增两种题型：① 听音选义 —— 只播发音、不显示单词，四选一中文释义；② 听音拼写 —— 只播发音，键盘拼出来。都挂在现有的 activeModes 开关体系下，用户可自由开关。
实现要点
关键设计是题干不能露出单词。现有题型渲染函数里「显示单词」的部分要按题型区分，否则一眼看到拼写就等于没测听力。需要在渲染层加一个 hideStem 分支。
参照产品
百词斩「听音选义 / 单词速听」、扇贝「听音辨义」、欧路「听写」

4 · 形近词辨析 P0

为什么值得做：affect / effect、adapt / adopt、principal / principle、desert / dessert —— 这类词是六级选词填空和改错的核心陷阱，而且靠背单个词是防不住的，必须并排对比才记得住。库里已有「近义词辨析」（13–15% 覆盖），但形近词完全空白。

怎么做（完全不依赖语料）
纯算法生成，不需要任何外部数据：在词库里找编辑距离 ≤ 2、长度差 ≤ 2、义项词性重叠 的词对，按「相似度高 + 词频都高」排序，取前 N 组做对比卡。放在「巧记」那一栏的末尾，或者独立一个「易混词」视图。
为什么这条路特别划算
近义词辨析和搭配之所以卡在 13–15%，是因为它们依赖源语料的规模（数据源里就没那么多）。而形近词是从词形本身算出来的，24027 个词条能立刻生成几千组，覆盖率只受词库规模限制，不受语料限制 —— 这是少数几个能「绕开数据天花板」的功能。

P1 · 值得做（工作量中等）

5 · 遗忘曲线图 P1

为什么：墨墨的招牌就是「遗忘曲线 / 记忆持久度 / 复习压力」三张图。词匠已经有 strength() 和每条的 [LAST, I, REPS]，缺的只是把「预测保留率」和「实际正确率」画成两条线做对照。有了这条对照，用户第一次能看见「算法准不准」，而不是盲信。

做法
横轴按「距上次复习的天数 / 当时设定的间隔」分桶，纵轴是实测正确率；再叠一条按 strength() 公式算出的预测线。

6 · 多轮正确才算掌握 P1

为什么：不背单词的做法是「同一个词至少要 3 次答对才算过」。现行的「一次答对即升阶」在选择题模式下有一个明确的漏洞：4 选 1 有 25% 的蒙对概率，蒙对之后算法会以为你记住了，把这个词的间隔拉长 —— 结果下次见面完全不认识。这是会真实损伤记忆算法准确性的问题。

做法
设置里加「连续答对 N 次才升阶」，默认 3。正确项必须连续、答错清零。需要新增一个计数字段（可用现有 prog 数组的空位）。

7 · 词根家族视图 P1

为什么：库里已有 927 个词根，但现在只能「在某个词的卡片上看到它属于哪个词根」，不能「从词根出发看它带出了哪些词」。不背单词的 5000+ 棵派生词汇树就是干的这件事，而词匠的数据其实已经够撑起这个视图了。

做法
新增一个按词根聚合的列表页：点词根 → 展开同根所有词（含各自档位），支持一键把这些词加入当前学习队列。

8 · 导出词表（CSV / Markdown / 可打印） P1

为什么：现在词匠只能导入不能导出 —— 这是个明显的不对称。真实用途很清楚：把错词本导出来打印、考前手写一遍；或者把生词本导出成 CSV 喂给别的工具。不背单词和欧路都支持导出，欧路甚至把「导出打印」当成卖点。

做法
在词库页加导出按钮，支持选范围（错词本 / 生词本 / 某本词书 / 全部）+ 选格式。纯前端 Blob 下载，不联网。

9 · 连续打卡天数 + 里程碑徽章 P1

为什么：扇贝、百词斩的「不想断签」是最强的留存机制。它不需要社区、不需要账号 —— 只要把 DB.log 里已有的日期连起来数一遍。用本地徽章（7 天 / 30 天 / 100 天 / 365 天）替代排行榜，能在不碰硬约束的前提下拿到同一种心理驱动力。

P2 · 锦上添花

  • 音节拆分（长词拆成 to-ma-to 式小块，辅助拼写）—— 参照背单词花园的自然拼读。
  • 例句挖空进单词卡 —— 读后练习里已有语境填空的实现，搬到单词卡上就是「读词填空」模式。
  • 周报 / 月报 —— 自动生成本周学习量、掌握率、薄弱词书，可导出。
  • 锁屏 / 后台听单词（手机端）—— 用 TTS 排队播报今日所学词，通勤时用。侵入性较大，需谨慎。
  • 升级到 DSR 难度模型（FSRS 思路）—— 把单一缓动因子拆成「记忆稳定性 / 难度 / 可提取性」三参数。理论收益明确（同样保留率下可减少 25–35% 复习量），但属于算法层重写，风险和验证成本都高。

五、明确不做的功能（附理由）

图片记忆（百词斩式）不做

理由：24027 个词条，每词配一张图，即使按每张 20KB 的强压缩算，也要给单文件产物加上约 480MB —— 而现在的 HTML 是 11MB、APK 是 4.2MB。这不是「优化一下」能解决的问题，是形态上的冲突。
另外百词斩自己的用户测评里也反复提到「容易记图不记词」「眼熟但说不出意思」，这套机制有它自己的代价。

影视原声例句（不背单词式 150 万条）不做

理由：双重不可行 —— 影视台词的版权不可能拿到，音频体积同样压不进单文件产物。词匠的替代路径已经有了：Tatoeba 例句（四六级 94–98% 覆盖）+ 文章精读提供的真实语境，这条组合其实覆盖了同一个需求。

云同步 / 打卡社区 / 组队 / PK / 排行榜 不做

理由：这五项全部需要账号体系与服务端，与「离线可用 + 数据不上传」两条硬约束直接冲突。要做其中任何一项，词匠就不再是词匠了。
替代方案已在 P1 里给出：本地连续天数 + 里程碑徽章。用户真正想要的是「不想断签」的推动力，不是「看见别人的排名」。

真题考频 / 考义高亮（不背单词式 17 万条）不做

理由：需要历年四六级真题语料，版权受限；且获取到的语料质量无法保证。这一项的价值确实高，但走不通，只能放弃。文章精读用的是公开媒体正文，这条路径是干净的。

AI 问答 / 自动造句 / 发音打分 不做

理由：全部需要联网调用模型，违反离线约束。发音打分还需要声学模型，体积和性能都不现实。

六、如果只做三件事

词汇量测试 + 考试倒计时反推 + 听力题型。

这三个补在三个真实的断点上：
· 「学之前不知道该从哪开始、每天学多少」 → 词汇量测试 + 倒计时反推（P0-1、P0-2，两项加起来是一个完整闭环）
· 「学的时候听力完全练不到」 → 听力题型（P0-3，六级最大权重的一块）
· 「背完了不知道离目标还差多远」 → 倒计时反推里的完成度预测

三项全部是零联网、不碰数据层、不动记忆算法的改动，改动面小、回归风险低，而且补上的恰好是市面产品靠「联网 + 云数据」才能做到、而词匠靠本地数据同样能做到的部分。

第四项 形近词辨析 单独说明它的特殊性：它是唯一一个能绕开数据天花板的功能 —— 近义词辨析和搭配卡在 13–15% 是因为源语料不够，而形近词是从词形直接算出来的，想扩多少有多少。如果时间允许，它应该和上面三项一起做。
